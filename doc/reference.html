mini-os32 reference

The language, the library, every syscall, graphics, and hardware access — one page, one search box.

Getting started

Build and boot from the repo root. -b rebuilds first, -k uses KVM (fast), -p boots the real image so writes persist across runs. Without -p you boot a scratch copy (build/run-uefi.img; the previous copy is kept as .prev).

./run-uefi.sh -k -b

Compile and run inside the OS. cc prompts for a space-separated source list, then an output name. lib/stdio.c is added automatically; every other library source (string.c, stdlib.c, gfx.c) must be listed — bare names are found in /lib automatically.

cc
source files: game.c gfx.c
output file:  game

run game

Editor: edit file.c. Ctrl+S saves and syncs to the persistent store (status shows saved+synced). Ctrl+U/Ctrl+D page up/down. Arrow keys move; exit returns to the shell.

Console scrollback: Shift+PgUp / Shift+PgDn page through the last 512 lines. Any new output snaps back to live.

The language

cc is a real C compiler for a consistent subset. What's listed here works; what isn't listed probably doesn't.

types

int, unsigned int, short/unsigned short (real 16-bit), long (= int, ILP32), char (signed/unsigned), float, bool/_Bool, void, pointers, arrays (multi-dimensional work), function pointers, struct/union/enum/typedef; static, extern, const, volatile. There is no double — float is the only floating type (~7 significant digits).

literals

Decimal and hex ints (123, 0x7B) with u/U/l/L suffixes; floats with exponents (1.5e3) and f suffix; chars 'a', '\n'; strings; escapes \n \t \r \a \b \f \v \e \\ \' \" \?, hex \x41, octal \101. Unknown escapes warn.

operators

All the usual: + - * / %, & | ^ ~ << >>, comparisons, short-circuit && || !, ?:, compound assignment, ++/-- (prefix and postfix), & *, . ->, sizeof.

Gotchas. ++/-- desugar to x = x + 1, so the lvalue is evaluated twice — a[f()]++ calls f() twice. Function arguments evaluate right to left: printf("%d %d", i++, i) will surprise you.
statements

if/else, while, do…while, for (with a declaration in the init clause), switch/case/default, break, continue, return, goto (forward and back; undefined labels are errors). Declarations are allowed inside blocks.

functions

Up to 16 parameters, call by value. Varargs via va_start/va_arg/va_end (builtins; include stdarg.h for the va_list typedef).

structs

Field access, sizeof, struct assignment and pass-by-value all work (the callee gets a copy). Returning a struct by value is rejected (ret struct unsupported) — return a pointer or fill an out-parameter instead.

initialisers

Braced initialisers for arrays and structs, nested; length inference (int a[] = {…}, char s[] = "…"); partial initialisers zero-fill. Locals may use non-constant expressions; globals must be constant. No brace elision: int m[2][2] = {{1,2},{3,4}}, never {1,2,3,4}.

Preprocessor

#include

"file.h" searches: the including file's directory → the working directory → the root → /lib. <file.h> searches: the root → /lib. So <stdio.h> works from anywhere. Depth limit 9.

#define & friends

#define NAME value, function-like macros up to 8 params, #undef, #if/#ifdef/#ifndef/#elif/#else/#endif, __LINE__, __FILE__. No ## or stringizing #. 256 macros max, 256-char bodies.

Line-based. The preprocessor reads one line at a time. Never open a /* … */ comment on a directive line and continue it below — the continuation lines get parsed as code. Put multi-line comments above the directive.

Library

Everything lives in /lib. Headers give prototypes; the .c file must be in your source list (except stdio, which is automatic).

stdio — automatic

putc, puts, readline, printf, snprintf, vsnprintf, scanf. puts does not append a newline. printf formats: %d %u %x %X %c %s %f %g %% with precision (%.2f). scanf: %d %u %x %c %s %f %e %g, reads one line per call, returns items assigned — check it. Floats are 32-bit: ~7 digits, %f switches to scientific outside 1e-4…1e9.

string.c — <string.h>

memcpy, memset, memmove, memcmp, strlen, strcmp, strncmp, strcpy, strncpy.

stdlib.c — <stdlib.h>

malloc, free, calloc, realloc, atoi, strtol. The heap grows via sys_sbrk toward the stack.

errno.h

extern int errno; codes ENOMEM (12), EINVAL (22).

stdint.h

int8_t/uint8_t, int16_t/uint16_t, int32_t/uint32_t.

path.c — <path.h>

cwd_get(), path_resolve(base, name, out, sz) (joins and folds ./..), path_fs (same + rejects names over the 47-char limit), path_dir, path_base. Needed only if your program takes relative paths itself.

Syscalls

Call through the wrappers below (declared in stdio.h — they are cc builtins, no extra source needed) or raw with syscall(n, …). Numbers live in lib/libc.h.

Files

int sys_load(char *name, void *buf, int max)

Reads a whole file into buf. Returns the size, or -1 if the file doesn't exist or is larger than max. -1 on a first run is normal — treat it as "no data yet".

int sys_save(char *name, void *buf, int size)

Creates or completely replaces a file with size bytes from buf. Returns 0 on success. The pattern is always load → modify in memory → save; there is no append.

sys_open / sys_fread / sys_fwrite / sys_close / sys_seek

Descriptor-based streaming I/O for files too big to hold in memory: sys_open(name, mode) (0 read, 1 write) returns an fd; then sys_fread(fd, buf, len), sys_fwrite, sys_seek(fd, pos), sys_close(fd).

int sys_list(void *buf, int max)

Fills buf with 52-byte records — 48 bytes of name, 4 bytes of size — and returns the count. Directory markers end in /. Size the buffer for 512 entries: 52*512.

sys_rename(old, new) / sys_delete(name)

Rename or delete. 0 on success.

sys_getcwd(buf, max) / sys_setcwd(path)

The kernel-held working directory. The shell publishes it on cd and re-reads it on restart, which is why your cwd survives run.

int sys_sync(void)

Flushes the whole RAM disk to the persistent store. 0 on success, nonzero when no store is attached. The editor calls this on every Ctrl+S.

Console & keys

sys_write(fd, buf, len) / sys_read(fd, buf, len)

fd 1 = screen, fd 0 = keyboard line input. printf/readline sit on top of these.

sys_getkey() / sys_getkey_nb()

One keypress: blocking / non-blocking (0 when nothing waits). Returns ASCII; arrows are 0x100–0x103, Delete 0x104, Escape is 27.

int sys_keystate(int sc)

1 while the key is physically held. The right choice for movement — several keys can be down at once, no repeat delay. Scancodes in stdio.h: SC_UP SC_DOWN SC_LEFT SC_RIGHT SC_W SC_A SC_S SC_D SC_Q SC_E.

sys_cls() / sys_setcursor(x, y)

Clear the text console / move the cursor.

Process, time, memory

int sys_exec(name)

Replaces the current program with another (this is what run uses). There is only ever one process.

void sys_exit(code)

Ends the program; the shell restarts. main returning does this for you.

int sys_ticks(void)

Milliseconds since boot. Measure frame time with it instead of assuming a fixed delay.

sys_sleep(ms) / sys_sleepf(ms)

Give up the CPU. sys_sleepf is the frame-friendly variant for render loops.

void *sys_sbrk(inc)

Grows the heap by inc bytes, returns the old break. malloc uses this; you rarely call it directly.

sys_thread_create(entry, stack) / sys_thread_exit()

A second thread of execution inside your program, with a stack you provide.

sys_meminfo / sys_storage / sys_poweroff

RAM totals (see hw/mem.c), NVMe + store info (see hw/storage.c), ACPI power-off.

Graphics

Compile with gfx.c in your source list. Full worked guide: type doc/gfx.txt; longer example: demo/move.c.

int gfx_fbinfo(gfx_fbinfo_t *out)

The way to draw: maps the framebuffer into your program. Fills w, h (pixels), pitch (bytes per row), bpp (8 or 32), size, user_addr (cast it to char * and write pixels). Returns <0 if no framebuffer.

The pitch trap. A row is pitch bytes, not w and not w*4. Compute offsets as y * pitch + x * 4 (32-bpp) or y * pitch + x (8-bpp), or your image shears diagonally.
writing pixels 
/* 32-bpp: 4 bytes, order blue-green-red-unused */
void put32(char *fb, int pitch, int x, int y, int rgb) {
    int off = y * pitch + x * 4;
    fb[off + 0] = (char)(rgb & 0xFF);          /* blue  */
    fb[off + 1] = (char)((rgb >> 8) & 0xFF);   /* green */
    fb[off + 2] = (char)((rgb >> 16) & 0xFF);  /* red   */
}
/* fill rows with an int pointer -- 4 bytes per store */
int *row = (int *)(fb + y * pitch);
for (int x = 0; x < w; x++) row[x] = rgb;

Always clip: writing outside w/h corrupts the next row or faults. In 8-bpp a pixel is one palette index — set every index you use with gfx_set_palette(idx, r, g, b) (0–255 each); nothing is set up by default.

int gfx_mode(int mode)

GFX_MODE_TEXT (back to the shell — always call this before returning), GFX_MODE_320x200x256, GFX_MODE_640x480x256, GFX_MODE_1440x900x32. On UEFI boots the firmware fixed the mode — a change may fail silently, so call gfx_fbinfo afterwards and use what it reports.

int gfx_blit(char *buf)

Pushes your own whole-screen buffer (8-bpp modes only). Simpler than direct drawing, slower.

the game loop 
int last = sys_ticks();
while (running) {
    int now = sys_ticks();
    int dt  = now - last;          /* ms since last frame */
    last = now;
    x = x + vx * dt / 1000;        /* speed in pixels/second */
    draw();
    sys_sleep(16);                 /* ~60 fps */
}

Erase and redraw only what moved — clearing the whole screen every frame is slow, and reading the framebuffer back is far slower than writing it. Keep your own copy of anything you need to read.

Hardware access

Direct hardware from user space, so drivers can be written in-OS. Friendly wrappers in hw/hw.c + hw/hw.h (add hw/hw.c to your source list); hw/lspci.c is a worked example. hw/hwtest.c (cd hw, cc hwtest.c hw.c, run hwtest) self-tests every syscall in this section against the NVMe controller, PASS/FAIL per check.

inb/inw/inl(port) — outb/outw/outl(port, v)

Port I/O, 1/2/4 bytes. (Raw form: sys_io_in(port, width), sys_io_out(port, width, value).)

pci_read(bus, dev, fn, off) / pci_write(…, val)

PCI configuration space, one dword at a time. Offset 0 is device<<16 | vendor; offset 8 has the class code in the top 24 bits; BARs start at 0x10. Absent devices read 0xFFFFFFFF. (Raw form packs bus<<16|dev<<8|fn into one arg.)

int sys_map_phys(phys_lo, phys_hi, size)

Maps physical device registers (e.g. a PCI BAR — possibly above 4 GB, hence two halves) into your address space, uncached. Returns a pointer, -1 on failure. Up to 16 MB per program.

int sys_dma_alloc(size, unsigned out[2])

Physically contiguous memory for DMA: fills out[0] with your pointer and out[1] with the physical address the device must be programmed with. No free — it lives until the program exits.

int sys_irq_wait(irq, timeout_ms)

Unmasks IRQ 0–15 and sleeps until it fires. Returns how many times it fired, 0 on timeout.

Files & persistence

The filesystem is flat: lib/stdio.c is one literal key, a "directory" is a name prefix (marked by a zero-size entry ending in /), and whole names cap at 47 characters including the prefix. Names are stored uppercase but matched case-insensitively.

dircontents
/libthe C library — all headers and sources
/hwhardware: hw.c/h wrappers, lspci.c, mem.c, storage.c, hwtest.c
/demomove.c (graphics), hello.s (assembly)
/docgfx.txt — the graphics guide
/srccc.c — the compiler compiles itself: src/cc.c string.c path.c

Where your data actually is: saves go to a RAM disk. sync (or the editor's Ctrl+S) copies the whole RAM disk to the store partition, which survives power-off. In QEMU without -p the store lives in the scratch image — recover files from any image with python3 tools/lsstore.py <img> --extract dir/ on the host. Files in the repo's fs/ directory are baked into every build and are the safest home for source you care about.

Reading a crash

USER EXC 0000000E ERR 00000004 EIP 00006171 ESP 017FFF78 EAX 00000001 EDX 00000028 CR2 584C030B

Your program did something illegal; the kernel printed the CPU state and killed it. How to read it:

fieldmeaning
EXC 0Epage fault — touched an unmapped address. CR2 holds which address: that's your bad pointer.
EXC 0Dgeneral protection — an address outside the 96 MB segment, or garbage executed as code.
EXC 00 / 06divide by zero / invalid instruction (often a wild jump landed in data).
EIPthe address of the faulting instruction, inside your program's code.
ESPthe stack pointer. The stack starts at 0x1800000 and grows down — ESP near that means shallow calls (in or near main); much lower means deep recursion.
EAX, EDXregister contents at the moment of death — often a recognizable value: a size you passed, a loop index, string bytes.
CR2page faults only: the exact address that was touched.

Usual suspects, in order: an uninitialized pointer, an array index past the end, a string that lost its NUL, using a value as a pointer (CR2 that looks like ASCII bytes = you dereferenced text).

Trap list — things that will bite you

  • Declaring ≠ initializing. int tries; holds garbage until you assign it. Always = 0.
  • puts adds no newline. End with \n yourself.
  • Arguments evaluate right to left. Don't put side effects in two arguments of one call.
  • a[f()]++ calls f() twice.
  • No struct return. Out-parameters instead.
  • Comments must not open on a #define line and continue below it.
  • Use pitch, never w, for framebuffer rows.
  • Restore text mode (gfx_mode(GFX_MODE_TEXT)) before returning from a graphics program — otherwise the shell is alive but invisible.
  • scanf returns the count assigned — check it; unmatched arguments keep their old values.
  • sys_load returns -1 for missing or too-big files. Both look the same.
  • Saved ≠ persistent. RAM disk until sync; editor Ctrl+S syncs for you.
  • Names cap at 47 chars including the directory.
